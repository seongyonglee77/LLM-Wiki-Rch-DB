# Research project operations

This is the shared workflow, not a mandatory linear pipeline. Use only the requested stage: brainstorming, internal search, evidence recording, methods, outline, drafting, revision or review. DB operations remain governed by DB `AGENTS.md`.

## Install once; initialize only active projects

From the downloaded DB directory, Python detects its location from the script itself:

```sh
python3 scripts/install_research_tools.py --apply --fetch-km
```

This installs project-init, project-literature and a bound KM search adapter in the user's Codex skills directory, and creates a sibling research-agents hub. Dependencies/checkout remain outside the DB. To preview without writes omit both --apply and --fetch-km. Use --skills-dir for GJC/AGY or another client; see research-tools-setup.md. No automatic bot, email access or scheduler is installed.

In the intended project session say **“이 프로젝트 표준 초기화해 줘.”** The skill previews and executes:

```sh
python3 "<DB>/scripts/project_init.py" --project "<project>"
python3 "<DB>/scripts/project_init.py" --project "<project>" --apply
```

Missing files only; no overwrite. Existing conflicting binding is an error. No mass initialization of historical projects. Folder opening does not initialize anything. Unknown facts remain Undecided. Root moves require explicit rebinding, not a silent guessed replacement.

## Canonical evidence schema

```json
{
  "schema_version": 1,
  "records": [{
    "record_id": "paper:<actual-registry-stem>",
    "card_path": "cards/<actual-registry-stem>.md",
    "citation_key": "<actual-registry-key>",
    "decision": "candidate",
    "decision_reason": "Proposed relevance; not yet adopted",
    "argument_role": "Specific LR argument, comparison or limitation",
    "evidence": [{
      "source_path": "sources/<actual-registry-stem>.md",
      "quote": "Exact quotation from the canonical source",
      "locator": "",
      "verification": "source_text",
      "interpretation": "What this passage supports and what it does not"
    }],
    "unknowns": ["Page locator not verified"],
    "reference": "Human-readable bibliographic reference from the actual DB metadata"
  }]
}
```

The example is a schema, not real evidence to import. Candidate records may have an empty evidence list. All identity fields must match registry. `candidate`, `selected`, `excluded` are decisions; `source_text`, `page_verified`, `unverified` are evidence states. Adoption does not prove a claim. A source text match does not establish page or semantic support. Never turn an abstract-only record into full-text verification. Only actual source page markers can support page_verified, and absence remains manual review. References prose is a display convenience; actual bibliography is the selected Bib subset and DB metadata.

The LLM prepares structured updates from the request, not the user. Keep input JSON in a project scratch file or OS temp; validate before writing:

```sh
python3 "<DB>/scripts/project_literature.py" --project "<project>" upsert --input "<update.json>"
# Only if the user actually selected these items:
python3 "<DB>/scripts/project_literature.py" --project "<project>" upsert --input "<update.json>" --approve-selection
python3 "<DB>/scripts/project_literature.py" --project "<project>" packet --record-id "<actual-id>"
python3 "<DB>/scripts/project_literature.py" --project "<project>" validate
python3 "<DB>/scripts/export_project_bib.py" --project "<project>"
python3 "<DB>/scripts/verify_draft_citations.py" "<draft.md>" "<project>/references.bib"
```

Repeated initialization is safe; literature upsert preserves non-target records. Generated views can be rebuilt. Tools verify paths, identity and quotations, not scientific merit or researcher approval provenance beyond the explicitly supplied selection operation. A successful CLI is not proof of semantic claim support. Recheck source evidence after DB changes; do not silently reuse stale claims.

## DB ↔ project links

Projects link to canonical DB records; no copied source/card archive. `agenda/projects/` is optional operational reverse navigation, not automatic wiki content. A user-requested project backlink may be created there separately, with project root, research question, IDs, status summary and last check date. It is not searched by KM or included in wiki-site. Publication of a completed project's reusable synthesis into wiki/projects is a separate explicitly authorized DB operation, reviewed for privacy; no automatic manuscript import.

## Permissions and resume

DB read-only; write within the active project only. Agent instructions are not filesystem permissions. Configure real sandbox paths for bots and tools. No token, venv, package/model cache, browser profile, SQLite runtime or session database in OneDrive. Source .py/.md templates may sync, while runtime state stays per-host. Do not run two writers against the same project/ledger; atomic file replacement is not a cross-device transaction. On ending a task, preserve canonical manuscript path and record verified results, unknowns and next actions in STATUS. A new session reads these files, not another machine's conversation memory.
